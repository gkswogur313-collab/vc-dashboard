# 산업 트래킹 주간 브리핑 — 작성 가이드

매주 월요일 Claude 예약 작업이 이 문서대로 지난주(월~일, KST) 브리핑을 만든다.
독자는 VC 심사역이다. 목적은 **기술 스터디**와 **업계 동향 파악**이다. 투자 추천은 쓰지 않는다.

## 절차

1. `node scripts/brief/collect.mjs` — 지난주 리포트 후보가 `tmp/brief-candidates.json`에 생긴다. 특정 주를 뽑으려면 주 시작일(월)을 인자로 준다.
2. 후보마다 `본문`(상세 페이지 텍스트)과 `PDF`(PDF 앞 6쪽 텍스트)가 들어 있다. 매일 수집 때 GitHub Actions가 미리 받아 둔 것이다(`data/industry-text.json`). **이 텍스트를 1차 원문으로 읽는다.**
   - 기술 스터디 주제 후보와 TOP 3 후보는 `PDF`·`본문`을 꼼꼼히 읽는다. 나머지는 제목과 첫 부분만 훑는다.
   - `원문확보: false`인 리포트는 필요할 때만 WebFetch로 상세 페이지를 열어 본다. 일부 사이트(IITP, BioIN 등)는 robots.txt로 막혀 있으니 재시도하지 않는다.
   - 끝까지 원문을 못 읽은 리포트를 인용할 때는 refs에 `"원문확인": false`를 넣고, 제목에서 확실한 내용만 쓴다.
   - 본문 텍스트는 목차·메뉴가 섞여 있을 수 있다. 내용과 무관한 문구는 무시한다.
3. `public/data/briefs/<주 시작일>.json`을 아래 형식으로 쓴다.
4. `node scripts/brief/validate.mjs public/data/briefs/<id>.json`을 실행한다. 통과하면 `index.json`이 갱신된다.
5. `node scripts/brief/build-docx.mjs public/data/briefs/<id>.json`을 실행하면 `public/briefs/<id>.docx`가 생긴다.
6. 두 파일과 `index.json`을 커밋하고 main에 push한다. 대시보드는 Cloudflare가 자동 배포한다.

## 작성 원칙

- **출처가 없는 문장은 쓰지 않는다.** 모든 사실 문장 끝에 `[n]`을 붙인다. n은 refs의 번호다.
- **리포트에 없는 숫자·전망을 만들지 않는다.** 배경 설명(기술 원리 등)은 일반 지식으로 써도 되지만, 수치·주장은 반드시 리포트에서 가져온다.
- **기술 스터디는 처음 보는 사람이 이해할 수준으로 쓴다.** 비유는 1개까지 쓴다. 약어는 처음 나올 때 풀어 쓴다.
- **업계 동향은 "무슨 일이 있었나 → 그래서 무엇이 달라지나"를 한 문장 안에 담는다.**
- **TOP 3는 산업·기술을 다룬 리포트를 최우선으로 고른다.** 특정 산업의 구조·시장·밸류체인, 또는 특정 기술의 원리·개발 동향·적용을 다룬 리포트가 1순위다(사용자 지정, 2026-11).
  - 그 안에서는 새로운 데이터, 구조적 분석, 기술 심층 해설이 있는 리포트를 우선하고, 단순 동향 모음보다 심층 리포트를 고른다.
  - **경제·금융 이슈(거시경제, 유가·환율·금리, 금융시장, 투자·창업 생태계, 일반 정책 제도 등)는 가장 후순위다.** 산업·기술 리포트로 3개를 채울 수 없을 때만 넣는다.
  - **산업·기술 리포트 중에서도 바이오·헬스케어보다 다른 분야(반도체, AI·소프트웨어, 로봇·제조, 에너지·모빌리티, 소재, 우주·국방 등)를 먼저 고른다.** 바이오는 다른 분야에 마땅한 리포트가 없을 때만 넣는다(사용자 지정, 2026-11).
  - 우선순위 요약: ① 비(非)바이오 산업·기술 → ② 바이오 산업·기술 → ③ 경제·금융 이슈.
  - 테마가 한쪽에 몰려도 괜찮다. 분산을 위해 순위를 바꾸지 않는다.
- 문체는 "~다" 체로 간결하게 쓴다. 한 문장은 80자 안팎으로 쓴다.
- 같은 기관 자료로 한쪽에 치우치지 않게 한다.

## JSON 형식

```json
{
  "id": "2026-10-26",
  "기간": { "from": "2026-10-26", "to": "2026-11-01" },
  "리포트수": 42,
  "한눈에": ["핵심 문장 [1][3]", "... (3~5줄)"],
  "기술스터디": [
    {
      "주제": "HBM 다음은 zHBM? — AI 메모리의 데이터 이동 병목",
      "한줄요약": "한 문장 요약",
      "무엇인가": "기술 원리 설명 2~4문장 [2]",
      "왜지금": "지금 주목받는 이유 2~3문장 [2][5]",
      "핵심포인트": ["포인트 [2]", "... (3~5개)"],
      "밸류체인": "어디에 누가 있는지 2~3문장 [5]",
      "더읽을거리": [2, 5]
    }
  ],
  "업계동향": [
    { "테마": "반도체", "시그널": ["시그널 문장 [4]", "... (2~4개)"] }
  ],
  "정독TOP3": [
    { "ref": 2, "이유": "왜 정독할 가치가 있는지 1~2문장", "읽는포인트": ["이 부분을 보라", "..."] }
  ],
  "키워드": "collect 결과의 keywords를 그대로 넣는다",
  "refs": [
    { "n": 1, "id": "41cbc33804bb", "원문확인": true }
  ],
  "메모": "선택: 원문 확인이 안 된 사이트 등 참고사항"
}
```

- `기술스터디`는 2~3개, `업계동향`은 테마 3~6개, `정독TOP3`는 정확히 3개다.
- `refs`에는 번호(n)와 리포트 id만 넣는다. 기관·제목·날짜·링크는 validate가 수집 목록에서 채운다.
- 업계동향 테마명은 대분류(반도체, AI·소프트웨어·데이터 …)를 기본으로 쓰고, 그 주에 두드러진 흐름이면 세부 테마(피지컬 AI·로봇, 배터리·이차전지 …)로 따로 뺄 수 있다. 같은 내용을 두 테마에 중복해 쓰지 않는다.
- 정독TOP3의 `이유`에 수치가 있으면 `[n]`을 붙인다. `읽는포인트`는 리포트 안에서 볼 부분을 가리키는 안내라 출처 번호가 없어도 된다.
- 정독TOP3는 기술 스터디에서 다룬 리포트와 겹쳐도 된다. 같은 테마에 몰려도 된다.
- 원문 텍스트에 목차만 있거나 이미지뿐인 리포트(예: KEIT 이슈픽)는 기술 스터디·TOP3의 근거로 쓰지 않는다.
