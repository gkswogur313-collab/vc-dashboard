## 반도체 브리핑과의 역할 분담 (중복 금지)

같은 날 07:37에 발행되는 **반도체 브리핑은 공급 쪽**(칩을 어떻게 만드나: 공정·소부장·메모리 공급·파운드리)을, **AI 브리핑은 수요·활용 쪽**(칩을 어떻게 쓰나: 가속기 경쟁, 추론 비용, 서버·랙 구성, 데이터센터 투자)을 맡는다.
- collect 결과의 `반도체브리핑`(같은 주 반도체 브리핑 시그널 제목 목록)을 먼저 본다. 그곳에 이미 실린 사건은 하드웨어 레이어에 다시 쓰지 않는다.
- 두 쪽에 다 걸치는 큰 소식(예: 엔비디아 실적, HBM 공급 계약)은 **AI 쪽 관점(수요·가격·고객)만** 짧게 쓰거나, `반도체연계`에 한 줄 요약만 남긴다("반도체 브리핑 ○○ 구간에서 다룸 — AI 쪽 함의: …").
- 반도체 브리핑이 아직 없으면(`반도체브리핑: null`) 공정·소부장 쪽 소식은 쓰지 않고 수요 쪽만 쓴다.
- 산업 트래킹 주간 브리핑(06:31)도 AI 리포트를 다룰 수 있다. 같은 연구기관 리포트를 깊게 다시 요약하지 말고, 정독 추천에만 올리거나 시그널 근거로만 쓴다.

## 절차

1. `node scripts/ai/collect.mjs` → `tmp/ai-candidates.json` (특정 주는 주 시작일 인자). `레이어`·`태그`는 제목 기준 자동 태그라 참고만 한다.
2. 후보를 훑어 AI와 무관한 글, 같은 내용의 중복 기사, 홍보성 행사 안내를 걸러 낸다.
3. 중요 후보는 원문을 읽는다. `본문`·`PDF`가 있으면 그걸 1차 원문으로 쓰고, 없으면 WebFetch로 원문을 연다. 구글 뉴스 링크(`구글경유: true`)는 열리지 않으니 WebSearch로 원문을 찾아 **외부 ref(원문 주소)**로 단다. 셸에서 curl 등으로 외부 사이트에 접속하지 않는다(차단됨).
4. 피드에 안 잡히는 것을 WebSearch(`extended`)로 보완한다. 최소 확인 목록:
   - 그 주 주요 모델 출시·업데이트(OpenAI·Anthropic·Google·Meta·xAI·DeepSeek·Qwen 등, 국내 독자 AI 파운데이션 모델 포함)
   - 그 주 실적·가이던스를 낸 빅테크·네오클라우드·AI 칩 기업(설비투자 수치)
   - 대형 투자 라운드·M&A·IPO(글로벌 상위 + 국내 AI 스타트업)
   - 국내 정책(과기정통부·AI 기본법 하위법령·국가AI컴퓨팅센터·GPU 확보 사업)
5. `public/data/ai/weekly/<주 시작일>.json`을 아래 형식으로 쓴다.
6. `node scripts/ai/validate.mjs public/data/ai/weekly/<id>.json` → 통과할 때까지 고친다(index.json 자동 갱신).
7. `node scripts/ai/build-docx.mjs public/data/ai/weekly/<id>.json` → `public/briefs/ai/<id>.docx`
8. **교과서 갱신** (아래 '교과서 갱신 규칙') → `node scripts/ai/textbook.mjs` (검증·출처 번호 정리·워드 재생성)
9. 같은 주 JH Weekly Report 워드가 이미 있으면 `node scripts/weekly/build-docx.mjs public/data/weekly/<id>.json`으로 다시 만들어 AI 브리핑을 반영한다.
10. 커밋·push: `public/data/ai`, `public/briefs/ai`, (9단계를 했으면) `public/briefs/weekly`.

## 작성 원칙

- **출처 없는 문장은 쓰지 않는다.** 사실 문장 끝마다 `[n]`. 보도 수치는 그대로 옮기고, 원문에 없는 숫자·전망을 만들지 않는다.
- **단일 매체 보도**(교차확인 안 됨)는 "~라고 보도했다"처럼 추정형으로 쓰고, 회사 반응이 있으면 같이 쓴다. 벤치마크 수치는 **누가 측정했는지**(회사 자체 발표인지, 제3자 평가인지) 밝힌다.
- **기간 밖 사건 금지.** 배경이 필요하면 "(배경, YYYY-MM)"으로 짧게.
- 시그널은 "무슨 일이 있었나 [n]" + `함의`(그래서 투자 검토·밸류체인에 무엇이 달라지나, 출처 없이 판단 문장 가능)로 쓴다.
- 모델 출시 소식은 '성능 자랑'보다 **가격(토큰당 비용), 컨텍스트·도구 사용 같은 실사용 변화, 오픈/폐쇄 여부**를 우선 쓴다.
- 국내는 상장사 공시·수주, 스타트업 투자, 정부 사업 선정을 우선한다. 주가 등락만으로는 쓰지 않는다.
- 문체 "~다" 체, 한 문장 80자 안팎.

## JSON 형식

```json
{
  "id": "2026-11-16",
  "기간": { "from": "2026-11-16", "to": "2026-11-22" },
  "자료수": 120,
  "한눈에": ["핵심 문장 [1][2]", "... (3~5줄)"],
  "숫자": [{ "지표": "MS 분기 설비투자", "값": "349억 달러", "설명": "전년비 +74% [1]" }],
  "레이어": [
    { "구간": "모델", "시그널": [{ "제목": "...", "내용": "... [4]", "함의": "...", "태그": ["정책·규제"] }] }
  ],
  "국내": [{ "기업": "업스테이지", "구분": "모델·투자", "내용": "... [9]" }],
  "반도체연계": ["엔비디아 실적은 반도체 브리핑 '설계·AI칩'에서 다룸 — AI 쪽 함의: 추론 수요 비중 확대 [3]"],
  "기술노트": [{ "주제": "MoE", "설명": "원리 설명 + 이번 주 맥락 [5]", "교과서": "ch08" }],
  "정독": [{ "ref": 16, "이유": "..." }],
  "교과서반영": ["24장 ②에 ... 추가", "9장 최근 업데이트에 ... 추가"],
  "키워드": "collect 결과의 keywords를 그대로",
  "refs": [
    { "n": 1, "id": "A-3a8d2a3ccb3e" },
    { "n": 2, "제목": "...", "매체": "...", "날짜": "2026-11-17", "링크": "https://..." }
  ],
  "메모": "선택"
}
```

- `자료수` = collect의 `자료수`. `키워드` = collect의 `keywords` 그대로.
- `레이어.구간`은 `인프라 · 하드웨어 · 모델 · 애플리케이션 · 피지컬 AI` 중에서 3~5개, 구간당 시그널 1~4개. `태그`는 `정책·규제`·`투자·회수` 중 0~2개.
- `숫자` 0~6개(설비투자·모델 가격·투자 금액처럼 비교 가능한 수치 우선 — 교과서 지표 장 참고), `국내` 0~10개, `반도체연계` 0~4줄, `기술노트` 1~2개(`교과서`는 관련 장 id), `정독` 0~3개.
- refs는 두 종류: 수집 목록에 있는 글은 `{n, id}`(피드는 `A-…`, 산업 트래킹은 원래 id) — validate가 매체·제목·링크를 채운다. 웹 검색으로 찾은 글은 `{n, 제목, 매체, 날짜, 링크(https)}`.

## 교과서 갱신 규칙 (`public/data/ai/textbook.json`)

반도체 교과서와 같은 원칙이다(scripts/semi/GUIDE.md의 '교과서 갱신 규칙'). 요약:

### ① 매주 — '최신 기술동향' 장(`자동갱신: true`) 본문
- 그 주 브리핑에서 구조적 의미가 있는 것(새 모델 세대·가격 체계 변화, 대형 인프라 계약, 정책 시행, 공식 전망 수정)만 반영한다. 단기 이슈·루머는 넣지 않는다.
- 기존 절 본문에 문단을 더하거나 고치고, 낡은 내용은 지우거나 과거형으로 고친다. 새 흐름이 두 주 이상 이어지면 새 절을 만든다(최대 8~9개).

### ② 매주 — 나머지 장의 `최근업데이트` 박스
- ①의 소식이 특정 장과 직접 관련되면 그 장의 `최근업데이트` 배열 **맨 앞에** `{ "날짜": 오늘, "브리핑": "<주 id>", "내용": "2~3문장 [n]" }`을 넣는다. 한 소식은 가장 관련 깊은 장 1~2곳, 한 장의 박스는 최대 6개.
- 그 장 본문에서 설명한 개념과 연결해 쓴다(예: "이 장의 MoE 구조가 실제로 …").
- 다른 장 본문은 매주 고치지 않는다. 사실 오류만 즉시 고친다.

### ③ 분기마다 — 본문 통합 개정 (1·4·7·10월의 첫 월요일 작업에서)
- `최근업데이트` 중 지금도 유효한 구조 변화를 해당 장 본문·표·도식·핵심정리·체크포인트·용어에 녹이고 박스를 비운다. 단기 이슈로 끝난 항목은 버린다.
- AI는 변화가 빠르다. 분기 통합 때 '모델 경쟁 구도'·'투자 지형'처럼 숫자가 많은 장의 표는 최신 수치로 다시 확인한다.

### 공통
- **이 책은 AI를 전혀 모르는 사람이 이 책만 읽고 이해할 수 있어야 한다.** 반도체 교과서와 겹치는 내용(GPU·HBM·데이터센터)도 이 책 안에서 완결되게 설명하고, 더 깊이는 장의 `참고`(`{ "책": "semi", "장": "chNN", "설명": "..." }`)로 연결한다.
- 새 개념은 비유 1개, 약어 풀이, 표·도식(`도식`: 종류 '흐름' 또는 '층')으로 설명한다. 새 용어는 해당 장 `용어`에 추가한다.
- 새로 인용한 자료는 `refs`에 `{n, 제목, 매체, 날짜, 링크}`로 추가한다(번호는 아무 큰 수 — `textbook.mjs`가 다시 매긴다).
- `개정이력` 맨 앞에 `{ "날짜", "버전": 직전+0.1, "내용", "브리핑" }`. 반영할 것이 없으면 교과서는 건드리지 않고 브리핑의 `교과서반영`을 비운다. 둘의 내용이 서로 맞아야 한다.
