# 반도체 브리핑 — 작성 가이드 (주간 브리핑 + 교과서 갱신)

매주 월요일 Claude 예약 작업이 이 문서대로 ① 지난주(월~일, KST) **반도체 주간 브리핑**을 쓰고 ② **반도체 교과서**를 갱신한다.
독자는 VC 심사역이다. 목적은 **소재·부품·장비부터 칩·정책까지 밸류체인 전반의 동향 파악**과 **교과서를 늘 최신으로 유지**하는 것이다. 투자 추천은 쓰지 않는다.

화면: 대시보드 › 산업 트래킹 › 🔬 반도체 브리핑 (위: 교과서, 아래: 주간 브리핑) · JH Weekly Report ③에도 같은 주 브리핑이 원본 그대로 들어간다.

## 자료처 (사용자 지정)

| 묶음 | 곳 | 어떻게 들어오나 |
|---|---|---|
| 시장·통계 | SEMI(semi.org/ko), 한국반도체산업협회(KSIA) | 피드(구글 뉴스 경유) + WebSearch |
| 국내 연구기관·정책 | 산업연구원, KEIT PD 이슈리포트, KDB미래전략연구소, 수은 해외경제연구소, 무역협회 IIT, KOTRA 해외시장뉴스, 소부장넷 | 산업 트래킹 수집(industry.json) + 피드 + WebSearch |

피드는 GitHub Actions `fetch-semi`가 매일 06:52 KST에 `public/data/semi/feed.json`으로 모은다(목록: `scripts/semi/feeds.json`).

## 절차

1. `node scripts/semi/collect.mjs` → `tmp/semi-candidates.json` (특정 주는 주 시작일 인자). `구간`은 제목 기준 자동 태그라 참고만 한다.
2. 후보를 훑어 반도체와 무관한 글(종합 매체의 일반 IT 기사, SEMI 행사 안내 페이지 등)과 같은 내용의 중복 기사를 걸러 낸다.
3. 중요 후보는 원문을 읽는다. `본문`·`PDF`가 있으면 그걸 1차 원문으로 쓰고, 없으면 WebFetch로 원문을 연다. 구글 뉴스 링크(`구글경유: true`)는 열리지 않으니 WebSearch로 언론사 원문을 찾아 **외부 ref(원문 주소)**로 단다. 셸에서 curl 등으로 외부 사이트에 접속하지 않는다(차단됨).
4. 피드에 안 잡히는 것을 WebSearch(`extended`)로 보완한다. 최소 확인 목록:
   - 그 주에 나온 SEMI 보도자료(장비 출하·웨이퍼 출하·팹 전망 등), SIA 월간 매출, 한국 반도체 수출(매월 1일), TSMC 월매출(매월 10일경)
   - 그 주 실적 발표가 있었던 장비·소재·메모리 기업
   - 국내 소부장 수주·공시·IPO
5. `public/data/semi/weekly/<주 시작일>.json`을 아래 형식으로 쓴다.
6. `node scripts/semi/validate.mjs public/data/semi/weekly/<id>.json` → 통과할 때까지 고친다(index.json 자동 갱신).
7. `node scripts/semi/build-docx.mjs public/data/semi/weekly/<id>.json` → `public/briefs/semi/<id>.docx`
8. **교과서 갱신** (아래 '교과서 갱신 규칙') → `node scripts/semi/textbook.mjs` (검증·출처 번호 정리·워드 재생성)
9. 같은 주 JH Weekly Report 워드가 이미 있으면 `node scripts/weekly/build-docx.mjs public/data/weekly/<id>.json`으로 다시 만들어 반도체 브리핑을 반영한다.
10. 커밋·push: `public/data/semi`, `public/briefs/semi`, (9단계를 했으면) `public/briefs/weekly`.

## 작성 원칙

- **출처 없는 문장은 쓰지 않는다.** 사실 문장 끝마다 `[n]`. 보도 수치는 그대로 옮기고, 원문에 없는 숫자·전망을 만들지 않는다.
- **단일 매체 보도**(교차확인 안 됨)는 "~라고 보도했다"처럼 추정형으로 쓰고, 회사 반응이 있으면 같이 쓴다.
- **기간 밖 사건 금지.** 배경이 필요하면 "(배경, YYYY-MM)"으로 짧게.
- 밸류체인 시그널은 "무슨 일이 있었나 [n]" + `함의`(그래서 소부장·투자 검토에 무엇이 달라지나, 출처 없이 판단 문장 가능)로 쓴다.
- 소재·부품·장비 구간을 최대한 채운다. 그 주에 정말 없으면 구간을 빼되, 밸류체인은 최소 3개 구간이다.
- 국내 기업은 상장사 공시·수주·IPO와 스타트업 투자 소식을 우선한다. 주가 등락만으로는 쓰지 않는다(급락·급등이 업황 해석과 연결될 때만).
- 문체 "~다" 체, 한 문장 80자 안팎.

## JSON 형식

```json
{
  "id": "2026-11-02",
  "기간": { "from": "2026-11-02", "to": "2026-11-08" },
  "자료수": 76,
  "한눈에": ["핵심 문장 [1][2]", "... (3~5줄)"],
  "숫자": [{ "지표": "10월 반도체 수출", "값": "564.4억 달러", "설명": "전년비 +259.4% [1]" }],
  "밸류체인": [
    { "구간": "장비", "시그널": [{ "제목": "...", "내용": "... [4]", "함의": "..." }] }
  ],
  "국내기업": [{ "기업": "주성엔지니어링", "구분": "장비(증착)", "내용": "... [9]" }],
  "기술노트": [{ "주제": "3D DRAM", "설명": "원리 설명 + 이번 주 맥락 [5]", "교과서": "ch03" }],
  "정독": [{ "ref": 16, "이유": "..." }],
  "교과서반영": ["15장 ①에 ... 추가"],
  "키워드": "collect 결과의 keywords를 그대로",
  "refs": [
    { "n": 1, "id": "F-3a8d2a3ccb3e" },
    { "n": 2, "제목": "...", "매체": "...", "날짜": "2026-11-01", "링크": "https://..." }
  ],
  "메모": "선택"
}
```

- `자료수` = collect의 `자료수`. `키워드` = collect의 `keywords` 그대로.
- `밸류체인.구간`은 `소재 · 부품 · 장비 · 메모리 · 파운드리·로직 · 패키징·테스트 · 설계·AI칩 · 정책·공급망` 중에서, 3~8개 구간, 구간당 시그널 1~4개.
- `숫자` 0~6개(업황 지표 우선 — 교과서 13장 표), `국내기업` 0~10개, `기술노트` 1~2개(`교과서`는 관련 장 id), `정독` 0~3개.
- refs는 두 종류: 수집 목록에 있는 글은 `{n, id}`(피드는 `F-…`, 산업 트래킹은 원래 id) — validate가 매체·제목·링크를 채운다. 웹 검색으로 찾은 글은 `{n, 제목, 매체, 날짜, 링크(https)}`.

## 교과서 갱신 규칙 (`public/data/semi/textbook.json`)

- **매주 바꾸는 곳은 15장 '최신 기술동향'이 기본이다.** 그 주 브리핑에서 구조적 의미가 있는 것(새 공정·제품 양산, 일정 변경, 정책 시행, 공식 전망 수정)만 반영한다. 주가·단기 이슈는 넣지 않는다.
  - 기존 절의 본문에 문단을 더하거나 고친다. 낡은 내용(이미 지난 일정, 뒤집힌 전망)은 지우거나 과거형으로 고친다.
  - 새 흐름이 두 주 이상 이어지면 새 절(⑦ …)을 만든다. 절은 최대 8개로 유지하고, 관심이 식은 절은 합치거나 뺀다.
  - 각 절의 `관전포인트`를 최신으로 유지한다.
- **13장 '2026년 숫자 요약'**은 WSTS·SEMI 공식 전망이 새로 나왔을 때만 숫자를 바꾼다(연도가 바뀌면 절 제목도 바꾼다).
- **1~12장(원리·공정·밸류체인)은 사실 오류나 구조 변화가 있을 때만** 고친다(예: 새 공정 방식이 표준이 됨, 국내 대표 기업 지형이 바뀜). 문체와 구성을 유지한다.
- 새로 인용한 자료는 `refs`에 `{n, 제목, 매체, 날짜, 링크}`로 추가한다. 번호는 아무 큰 수(예: 101부터)를 써도 된다 — `textbook.mjs`가 처음 나오는 순서로 다시 매긴다.
- `개정이력` **맨 앞에** `{ "날짜": 오늘, "버전": 직전+0.1, "내용": "무엇을 바꿨는지 한 줄", "브리핑": "<주 id>" }`를 넣는다. 반영할 것이 없으면 교과서는 건드리지 않고, 브리핑의 `교과서반영`을 비운다.
- 브리핑의 `교과서반영`과 교과서의 `개정이력` 내용이 서로 맞아야 한다.
